
# SR-04 — DDoS Protection and Rate Limiting

## Requirement
The Vote Counting and Tabulation subsystem shall apply rate-limiting and denial-of-service mitigation measures 
to reduce the impact of excessive or malicious requests.

## Owner
Rosie

## Status
Analysis only — not implemented in the prototype.

## Security objective
Maintain service availability for legitimate users
during excessive or malicious traffic.

## Threats
- Excessive requests to application endpoints
- Automated request floods
- Resource exhaustion
- Legitimate users being unable to access services

## Priority
Medium

## Complexity
Medium


## Proposed solutions

### Solution A — Application-level rate limiting
Limit how many requests a user or client can send to an endpoint within a specified time window. This is relatively inexpensive and straightforward to demonstrate in a prototype. However, it may not stop large distributed denial-of-service attacks that overwhelm the network or infrastructure.

### Solution B — Reverse proxy or Web Application Firewall (WAF)
Filter and inspect incoming traffic before it reaches the application. A reverse proxy or WAF can help block suspicious requests and enforce traffic rules. Configuration and maintenance are required, and protection depends on the deployed service and its capacity.

### Solution C — Managed network-level DDoS protection
Use a cloud or network provider's DDoS mitigation service to detect and filter malicious traffic before it reaches the application infrastructure. This can offer stronger protection against large traffic floods, but may introduce subscription costs and dependency on the provider.
